# Agent-Only Social Media as a Testbed for Psychosocial Interventions

Code and records for the paper *What Is Agent-Only Social Media For? A Self-Stigma Intervention as a First Test*
(SocialAgent @ NeurIPS 2026).

A Patient agent posts in a support thread and is answered either by a Peer agent (intervention) or by a General
agent, an ordinary user (control). The Patient's self-stigma is carried across sessions as an explicit belief state,
revised after each session by a belief update, and scored each session on the ISMI-29 scale by an LLM judge.

## Layout

```
simulation/experiment/       # the 1:1 experiment: agents, belief update, judge, run records and analysis; the
                             #   evaluation set and search loops of the belief update; the longitudinal check
simulation/sanitychecking1/  # Section 4.1: static measurement validity (Figure 5)
simulation/sanitychecking2/  # the dialogue generator behind the evaluation set (Section 4.2)
```

**Start with [`simulation/experiment/`](simulation/experiment/).** Its README covers regenerating every table and
figure from the released records (CPU only), rerunning one persona x severity cell and scoring it (GPU), and the
evaluation set and search loops used to develop the belief update. Each folder has its own README.

| Paper | Where |
|---|---|
| Section 3, Appendices B–C (agents, belief update, judge, prompts, settings) | `simulation/experiment/agents/` |
| Section 4.1, Appendix D.1, Figure 5 | `simulation/sanitychecking1/` |
| Section 4.2, Appendices E–F, Figure 7 (evaluation set, search loops) | `simulation/experiment/evalset/`, `development/` |
| Section 4.2, Appendix D.2, Figure 6 (belief state vs accumulated dialogue) | `simulation/experiment/analysis/a4_*.py`, `results/validity/`; dialogues generated by `simulation/sanitychecking2/` |
| Section 5, Appendix G (results tables and figures) | `simulation/experiment/results/`, `analysis/` |

## Requirements

**Local models.** Qwen3-14B (dialogue and belief update) and Qwen3-32B (ISMI judge), served with
[Ollama](https://ollama.com) (Q4_K_M; the 32B model fits one 24 GB GPU):

```bash
ollama pull qwen3:14b
ollama pull qwen3:32b
```

**API models.** GPT-4o generated the Patient personas and the ten levels of Section 4.1; GPT-5.5 wrote the two
example dialogues in `simulation/sanitychecking2/data/synthetic/`; Claude Opus and Sonnet generated and checked the evaluation set. None of them is needed to
rerun the experiment from the released personas or to regenerate the tables and figures.

**Python.** `pip install -r requirements.txt`.

## Minibook

The environment is modelled on [Minibook](https://github.com/c4pt0r/minibook), a self-hosted agent-only social
network (revision `b19c61e`): each session is one thread, an opening post by the Patient followed by replies. The
reported runs generated these threads in process with that structure. `simulation/experiment/minibook/` writes the
released threads to a running Minibook instance through its REST API and reads each one back to check it, so the
reported dialogues can be browsed as platform threads. Minibook is a separate project and is not vendored here; cite
it alongside this work:

> c4pt0r. *Minibook: a self-hosted, agent-only social network.* 2026. https://github.com/c4pt0r/minibook

## Note on the ISMI-29 items

The judge is prompted with the ISMI-29 items, so their text is in `simulation/experiment/agents/ismi29_items.py`.
The scale is the work of its authors (Ritsher, Otilingam, and Grajales, 2003); consult the original for the
authoritative wording and any terms governing reuse. The item module is kept apart from persona generation on
purpose: if the items reached the generation side, a measured score would echo the questionnaire rather than
describe the persona.
